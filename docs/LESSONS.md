# บทเรียนของพวกเรา · Mochi Mayhem

ถอดบทเรียน 13 พ.ย. 2026 (v8.1.138) · จากประวัติจริง: ~2 เดือน (v2 กลาง ก.ย. → v8.1.138) · commit 313 · `game.js` 24k บรรทัด · เทส 175 · ใบสั่งอาร์ต 87 · asset 2.8 GB · บางวันขึ้นเวอร์ชัน 30+ ครั้ง
เจ้าของ + AI ฝั่งโค้ดใช้เอกสารนี้เป็น **กติกาทำงานร่วมกัน** · AI ทุกตัวอ่านก่อนเริ่มงานใหม่

## สิ่งที่ทำถูก (ทำต่อ)
1. เจ้าของเทสบนมือถือจริง ส่งภาพหน้าจอ + อาการตรง ๆ
2. ล็อกการตัดสินใจเป็นลายลักษณ์อักษร (CLAUDE.md §2)
3. เลือกแก้ความเสถียรก่อนเพิ่มฟีเจอร์
4. มีเทสครอบเยอะ แก้ของเก่าไม่พังของอื่น
5. ระบบใหม่ทำโค้ดด้วยภาพชั่วคราวก่อน แล้วอาร์ตตามมา (ห้องสมบัติ v8.1.122 → อาร์ต v8.1.137)

## วิธีทำงานต่อจากนี้
| ขั้น | ทำอะไร |
|---|---|
| 1. ตั้งเป้ารอบ | ธีมเดียวต่อรอบ เช่น "10 นาทีแรกของผู้เล่นใหม่" |
| 2. ส่งงานเป็นชุด | 5–10 ข้อ · หน้าไหน → เห็นอะไร → อยากเห็นอะไร |
| 3. ระบบใหม่ทำของปลอมก่อน | เล่นด้วยภาพวาดด้วยโค้ด/อีโมจิ ชอบแล้วค่อยสั่งอาร์ต |
| 4. ใบสั่งอาร์ตบอกจุดต่าง | ดูภาพรวมทั้งชุดก่อนผูกทุกครั้ง |
| 5. ขึ้นเวอร์ชันรอบละครั้ง | พร้อม checklist ให้เทส |
| 6. เคลียร์ "รอ QA" ก่อนเริ่มของใหม่ | ปิดของเก่าให้จบ |
| 7. งบหน่วยความจำ/FPS เป็นกฎเหล็ก | อาร์ตใหม่ต้องบอกว่ากินเท่าไร |
