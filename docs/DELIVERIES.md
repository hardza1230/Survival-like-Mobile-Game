# Latest delivery: v8.3.19 — Berry Blast sound and aim, no Shovel prize, walk-to-start side events
Owner bug round: (1) Berry Blast (Strawberry shotgun Unique) lost its firing sound in 8.3.16 — `releaseBerryBlast` (`src/20-…`) plays `uq_sniper_fire` again (owner's v6.82.2 choice). (2) The aim cone art `bpx_momo_aim_cone` has a transparent left margin (cone apex at x=115, tip at x=379 of 512), so the drawn cone started ~120 px in front of the hero while damage starts at the hero; now `setOrigin(115/512,.5)` and `setScale(R/264,…)` put the apex on the hero and the tip at R=300. (3) Mini-boss prize wheel drops the "Shovels" slot (Temple Depths is retired) — `miniPrizePool` 10 slots (`src/28-…`). (4) Chapter 1 side objects (`src/24-…`): no coloured circle before start (circle kept only while a hold-type event runs, to show the area), no tap-to-start (v8.3.13 tap could start an event by a stray movement touch), label "Walk here to start"; a running side event is no longer silently cancelled when the wave ends (`clearChapterCombatWave` ends it only with `all`) — that was why objects appeared and then vanished. Tests: `reward-ui` expects 10 wheel slots without Shovel; `owner-round-8315` covers the rest.

# Previous delivery: v8.3.18 — APKs signed with one fixed key (install over the old app)
Owner: the Store APK 8.3.17 would not install over 8.3.16 ("package conflicts with an existing package"). Cause: `android.yml` cached `~/.android/debug.keystore`, but that path never existed on the runner (log: "Cache not found" on restore, "Path Validation Error … no cache is being saved" on save), so every build signed with a fresh random debug key. Fix: a fixed test key `android-signing/ci-debug.keystore` (debug-only, password `android`, not the Play upload key) is committed; `scripts/set-android-version.mjs` adds a `signingConfigs.debug` pointing at it to `android/app/build.gradle`, so both the live-update debug APK and the Store APK use the same key from now on. Removed the useless cache steps; the SHA-1 print now reads the fixed key (store job prints it too): `E8:36:41:F5:47:94:C7:64:E9:33:ED:15:C8:80:67:04:E2:92:73:1F` — native Google login needs this SHA-1 in the Android OAuth client. One-time: phones must uninstall the old APK once (save: log in to cloud first). Test: new `tests/apk-signing-8318.test.cjs`.
