### A. ชีตร่าง 2–3 ของคู่หู (6 ชีต) — พื้นโปร่งใส
ทุกชีต **ใช้เลย์เอาต์เดียวกับชีตร่าง 1 เป๊ะ** เพราะโค้ดเปลี่ยนแค่ชื่อ texture (`'yz_'+kind+'_f'+form`) แล้วใช้เลขเฟรมเดิม:
- **8 เฟรม × 256×256px เรียง 4×2 = 1024×512** · ซ้าย→ขวา บน→ล่าง ไม่มีช่องว่าง/เส้นคั่น
- **แถวบน เฟรม 0–3 = เดินวนลูป** (เฟรม 0 = ท่ายืนพัก ใช้ตอนหยุดนิ่งด้วย)

  - pomelo = ตีกวาด (sweep) · lime = ดึงธนูยิง (bow) · bloodorange = ร่ายเวท (cast) — ทิศ/จังหวะเหมือนร่าง 1
- **เท้าแตะเส้นพื้นที่ y = 248** ทุกเฟรม · ตัวกลางเฟรมแนวนอน · **หันขวา** (โค้ดกลับด้านเอง)
- ตัวใหญ่เต็มเฟรมพอ ๆ กับร่าง 1 (crop/สัดส่วนเดียวกัน) — **โค้ดขยายขนาดบนจอให้เองแล้ว** ห้ามวาดตัวเล็กลงเพื่อเผื่อ ห้ามล้นขอบเฟรมทุกเฟรม (รวมธนู ไม้เท้า ผ้าคลุม ปีก)

## ข้อห้าม
- ห้ามมีตัวหนังสือ ตัวเลข อักษรเวท/รูนที่อ่านเป็นตัวอักษร ลายน้ำ โลโก้
- ห้ามเปลี่ยนหน้า ตา สีหลัก ผิวเปลือก ของตัวละคร — ต้องจำได้ว่าเป็น Pomelo/Lime/Blood Orange ตัวเดิม (เทียบภาพร่าง 1 วางคู่กันใน `review.png`)
- ห้ามดูน่ากลัว/ดุร้าย (ไม่มีหนาม เขี้ยว ตาแดงโกรธ) — "เท่ขึ้นแต่ยังน่ารัก" แบบขนม
- ห้ามมีเงาบนพื้นในชีตตัวละคร (โค้ดวาดเงาเอง) · ห้ามพื้นหลัง/กรอบ · alpha จริง ไม่มีฮาโลขาว
- ห้ามของสวมใส่หลุดขอบเฟรมในเฟรมใด · ห้ามวาดลูกธนู/กระสุน/วงเวทที่พุ่งออกนอกตัว (โค้ดมี FX แยกแล้ว)
- เฟรม 0 ของทุกชีตต้องเป็นท่ายืนที่ดูดีเมื่อหยุดนิ่ง · เฟรม 7 ต่อกลับเฟรม 0 ได้เนียน
- FX พื้นดำต้องดำสนิท #000 ไม่มี vignette/noise · ห้ามวาดตัวคู่หูใน FX

## โน้ตฝั่งโค้ด
- **จุดใช้ (มีแล้ว v8.0.90):** `yuzuVisual(m)` ใน game.js เลือก `fk='yz_'+m.kind+'_f'+form` ถ้า `form>1 && textures.exists(fk)` แล้วใช้เฟรม `pose.frame%8` (จาก `yuzuVisualPose`: เดิน 0–3, โจมตี 4–7) → ชีตใหม่ใช้ได้ทันทีเมื่อลงทะเบียน · ถ้าไม่มีไฟล์ = ภาพร่าง 1 ขยาย (+12%/ร่าง หรือ Pomelo ตาม growth) เหมือนเดิม
  - ⚠️ ตอนนี้เมื่อมีชีตร่าง ตัวมันจะ **แทน** คลิปพิเศษ `yz_48_<kind>` (16 เฟรม) และ `yz_47_<kind>` (windup/roll/land) ด้วย — ท่าพิเศษจาก `yz_47` ที่ใช้เฟรม 0–3 จะแสดงเป็นเฟรมเดินของชีตร่าง ยอมรับได้ แต่ตอนผูกให้ตรวจว่าท่าโจมตีของ `yz_48` (เฟรม 8–15) ไม่ถูก `%8` ไปชี้ผิดท่า (ถ้าผิดให้ map 8–11→4–5, 12–15→6–7)
  - `form` มาจาก `yuzuForm(m)`: Pomelo `[1,2,2,3][growth]`, Lime/Blood Orange `m.form` จาก `yuzuFormKills` (`YUZU_FORM_KILLS=[14,32]`)
- **FX:** `yuzuEvolveFx(m)` ตอนนี้ใช้ `screenFlash` + `vfxHitRing` → เพิ่มเล่น `yz_fx_evolve` 8 เฟรมครั้งเดียว (~0.6 วิ, ~13 fps) ที่ `m.spr` ย้อมสีตามชนิด (0xffd466 / 0xb7ff7c / 0xef91c8) เก็บ ring/flash เดิมเป็น fallback · **ห้ามใช้ `yuzuFx()` ตรง ๆ** เพราะมันวนแค่เฟรม 0–3 และ alpha .62 — ทำเส้นทางเล่น 8 เฟรม (หรือเพิ่ม option frames:8) และล้างพร้อม owner/epoch แบบ `_yzFx` (cap 8)
  - ⚠️ ใช้ key **`yz_fx_evolve`** (ไม่ใช่ `vfx_yz_evolve`) เพราะ `artHero()` จัดเฉพาะ key ที่ขึ้นต้น `yz_` เป็น hero-lazy ของ Yuzu — `vfx_*` จะไม่ถูกจัดเป็นของ Yuzu
  - พื้นดำ → pack script แปลงความสว่างเป็น alpha (NORMAL blend) แบบ `vfx_yzs_sour_burst` ใบ 56
- **ป้ายร่าง (ถ้ามา):** วาดข้าง `m.label` ใน `yuzuVisual` เฟรม `form-1` ย้อมสีตามชนิด · ไม่มีไฟล์ = ไม่วาด
- **ลงทะเบียน:** `ASSET_SHEETS` URL แบบ literal เช่น `yz_pomelo_f2:{url:'assets/art/yuzu_forms63/yz_pomelo_f2.webp',frame:<ขนาดเฟรมหลังแพ็ก>}` (build-www คัดลอกเฉพาะ path ที่เขียนตรง ๆ) · ทุก key ขึ้นต้น `yz_` → `artHero()` คืน `'yuzu'` → `artClass()` = `'hero'` โหลดเฉพาะตอนเลือก Yuzu **ห้ามโหลดตอนบูต**
- **Pack script:** `scripts/pack-yuzu-forms-63.py` ตามแบบ `scripts/pack-yuzu-companions.py` / `pack-yuzu-seedlings-56.py` (crop/scale เดียวกับร่าง 1, foot anchor y=248, lossless alpha WebP) → `assets/art/yuzu_forms63/`
- **งบ GPU:** Yuzu ใกล้เพดานแล้ว (~299/300 MB ตาม `tests/gpu-memory-budget.test.cjs`, ดูใบ 56) · ชีต 1024×512 = 2 MiB ถอดรหัสต่อแผ่น ×6 = 12 MiB เกินแน่ → **แพ็ก 50% (เฟรม 128px → 512×256 = 0.5 MiB/แผ่น)** และ/หรือ **โหลดเฉพาะ 2 ชีตของชนิดที่เลือกในรันนั้น** (lazy ตอนเริ่มด่าน/ตอนร่าง 2 ใกล้มา) · FX 8 เฟรมแพ็ก 50% = 0.5 MiB · ตรวจเทส GPU ก่อนปล่อย
- เพิ่ม regression test (เช่น `tests/yuzu-forms-63.test.cjs`): key ครบ, URL literal, artClass='hero', fallback เมื่อไม่มี texture
- อาร์ตเดิมทุกชิ้นเป็น fallback ห้ามลบ
