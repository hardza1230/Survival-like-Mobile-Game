## ทำไมต้องแก้ (ตรวจอัตโนมัติ 316 ชีตตัวละคร/มอน · 1,543 ภาพ · 590 VFX + ดูด้วยตา)
1. **ภาพโดนขอบเฟรมตัด**: ผม/อาวุธ/แสงเรืองยื่นเกินขอบเฟรม → ในเกมเห็นเป็น**เส้นตรงตัดกุด**
2. **ตัวหดตอนเปลี่ยนท่า**: ชีตท่าโจมตีวาดตัวเล็กกว่าชีตวิ่ง ทำให้ตัวละครหดวูบทุกครั้งที่โจมตี (ชุดปกติแก้ด้วยโค้ดไปแล้ว v8.2.7/8.2.9 แต่**ชุดสกินยังหด** เพราะใช้ตัวคูณเดียวกับชุดปกติ)
3. **เท้าลอย/จม**: จุดยืนเลื่อนขึ้นลงระหว่างเฟรม 15–19 px ทำให้ตัวเด้งทั้งที่ไม่ได้ตั้งใจ
4. **เศษภาพค้าง** จากเฟรมข้างเคียง

**หลักการแก้ทุกแถว:** ใช้**ภาพเดิมเป็นต้นแบบ** (ห้ามออกแบบใหม่ ห้ามเปลี่ยนหน้าตา สี ท่า) · ขนาดไฟล์ จำนวนเฟรม และลำดับเฟรม**เท่าเดิมเป๊ะ** · ทุกเฟรมต้องมี**ขอบว่างโปร่งใสอย่างน้อย 4% ทุกด้าน** (128 → 5 px · 256 → 10 px) รวมแสง/ผม/อาวุธ/เศษใบไม้ · ส่ง master ขนาด 2 เท่า (เฟรม 256/512) ได้ ฝั่งโค้ดย่อเอง

## MANIFEST
แต่ละแถว: `key`, `file`, `replaces` (path ต้นฉบับ), `bytes`, `sha256`, `width`, `height`, `frameWidth`, `frameHeight`, `frameCount`, `columns`, `background`, `minMarginPx` (ขอบว่างที่น้อยที่สุดของทุกเฟรม ต้อง ≥ 4% ของเฟรม), `bodyHeightRatio` (กลุ่ม A/B: ความสูงตัวเทียบชีตวิ่ง), `contentScale` (กลุ่ม C: ย่อจากเดิมกี่ % เช่น 0.9)

## โน้ตฝั่งโค้ด
- แพ็ก `scripts/pack-art-fixes84.py`: ตรวจ sha/bytes/ขนาด → เขียนทับไฟล์ต้นฉบับใน path เดิม (WebP q80) ให้ key เดิมใช้ได้เลย · ตรวจขอบว่างอีกรอบด้วยสคริปต์ตรวจแบบเดียวกับที่ใช้เขียนใบนี้ (`clipped` = 0)
- กลุ่ม A/B: แก้ `BP_POSE_SCALE` ตามขนาดใหม่ (Mint attack 1.23 → ~1.0 ถ้าวาดสูงเท่าชีตวิ่ง) · ถ้าตัวคูณของชุดปกติกับสกินต้องต่างกัน ให้เพิ่มตัวคูณราย texture ของสกิน (ตอนนี้สกินถูก rename เป็น key ปกติ จึงใช้ตัวคูณเดียวกัน)
- กลุ่ม C: คูณสเกลแสดงผลของมอน/บอสนั้นด้วย `1/contentScale` (เช่น `baseScale` / ขนาดบอส) ให้บนจอเท่าเดิม · ฮิตบ็อกซ์ไม่เปลี่ยน
- เทส: `tests/art-fixes84.test.cjs` (MANIFEST · ทุกเฟรมมีขอบว่าง ≥ 4% · ขนาดไฟล์เท่าเดิม)
